# The analysis environment: everything that reads a committed artefact and turns it into a
# number. Python 3.14.6.
#
# Two interpreters are in play and one file cannot describe both. The capture and scoring passes
# need torch and are pinned in requirements.txt; every producer of a table, a figure or a
# runs/*.json value runs here, where there is no torch. requirements.txt used to say it held "the
# versions every reported number was produced under" -- it did not. Every reported number is
# emitted by run/canon.py, which runs under this file's numpy 2.4.6 and not that file's 2.5.2.
#
# What the difference costs, measured rather than assumed:
#
#   - out/tables/*.tex and docs/RESULTS.md come out BYTE-IDENTICAL under both interpreters. Every
#     number in the paper is robust to it, and README.md's reproduction path does not depend on
#     this pin. It is here so the claim can be checked, not because the claim is fragile.
#   - out/canon.json does not: 94 lines differ in their last one or two digits, all inside the
#     leave-one-out prediction block, from linear-algebra reassociation. Nothing reads those
#     digits; out/ is not committed.
#   - The probe-fitting producers do not, and that is what this pin is for. numpy 2.4.6 against
#     2.5.2 flips one tied logistic-regression prediction in q3b4_real_3b/counting and two in
#     ivl_real_3b/glyph -- 3 of 1125, moving two cells by 1.3 pp. Re-deriving runs/*.json from the
#     state files under a different numpy does not reproduce the committed files, and the state
#     files are the one input a clone does not carry, so nothing else would catch it.
#
# run/verify_protocol.py check 27 asserts that every third-party import of the analysis path is
# named here, and reports the running versions against it.
